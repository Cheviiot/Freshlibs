# Участие в Freshlibs

Freshlibs упаковывает системные библиотеки, которые в ALT p11 устарели или
собраны без нужных плагинов. Пакет здесь **вытесняет** дистрибутивный, а не
встаёт рядом с ним, поэтому требования к рецепту жёстче, чем в обычном
репозитории приложений.

## Среда разработки

- ALT Linux p11, Stapler `v0.1.1` или новее.
- `stplr build` доустанавливает сборочные зависимости в ту систему, где
  запущен, — это не изолированная сборка.
- Проверять готовый пакет на живой машине **не нужно**: см.
  [Проверка в контейнере](#проверка-в-контейнере).

```bash
git clone https://github.com/Cheviiot/Freshlibs.git
cd Freshlibs
stplr build -s libdecor-0/Staplerfile          # --clean пересобирает с нуля
```

## Перед изменением

Проверяйте фактические имена пакетов и путей, а не предполагаемые — в ALT они
часто не совпадают с upstream и с другими дистрибутивами:

```bash
apt-cache policy <пакет>          # существует ли такое имя в p11
rpm -ql <установленный-пакет>     # какие файлы он занимает
rpm -q --provides <пакет>         # какие provides нужно повторить
rpm -q --requires <пакет>         # в каком виде записаны зависимости
apt-cache rdepends <пакет>        # кто от него зависит
```

Типичные ловушки p11: `libdecor` — имя только src.rpm, бинарные пакеты зовутся
`libdecor-0` и `libdecor-devel`; пакета `libwayland-devel` не существует,
есть `wayland-devel` (в нём `wayland-scanner`), `libwayland-client-devel` и
`libwayland-cursor-devel`.

## Требования к рецепту

- **Имя пакета совпадает с именем бинарного пакета ALT**, а не с именем
  upstream-проекта или src.rpm. Тогда `Provides` и `Conflicts`, которые Stapler
  добавляет к `name` автоматически, попадают на нужное имя. Каталог рецепта
  называется так же — документация Stapler требует точного совпадения с `name`.
- **`epoch=1`** у всех пакетов, вытесняющих системные.
- **`replaces`** (→ `Obsoletes`) перечисляет все системные пакеты, чьи файлы
  попадают в наш: runtime, devel и, если такие есть в других дистрибутивах,
  отдельные пакеты плагинов.
- **`provides`** дублирует системные имена в версионном и безверсионном виде,
  чтобы разрешались и `libdecor-devel`, и `libdecor-devel >= 0.2`.
- **`auto_reqprov_method='rpm'`** с `auto_req=1` и `auto_prov=1`, плюс
  `rpm-build` в `build_deps`. Это обязательно: только ALT-овые
  `/usr/lib/rpm/find-{provides,requires}` генерируют set-version-зависимости
  вида `libdecor-0.so.0()(64bit) = set:…`, от которых зависят пакеты p11.
  Универсальный метод `dirty` их не даёт, и такая библиотека не удовлетворит
  существующие обратные зависимости.
- **`--libdir=/usr/lib64`.** На ALT `/usr/lib64` — настоящий каталог
  64-битных библиотек, а `pkg-config` ищет только в
  `/usr/lib64/pkgconfig:/usr/share/pkgconfig`. Определяйте libdir в
  `prepare()`, не полагайтесь на `/usr/lib`.
- **`compatible_with=('altlinux')`**: имена сборочных зависимостей и раскладка
  каталогов здесь специфичны для ALT.
- **`files-find-binary` не используется**, если пакет не ставит исполняемых
  файлов: хелпер завершается ошибкой на пустом `/usr/bin` и роняет сборку.
- Каждый пакет содержит и runtime, и devel-часть. Системный devel-пакет владеет
  теми же заголовками, `.pc` и symlink `.so`, поэтому его заменяют, а не
  оставляют рядом.

## Восстановление состояния

Прямое удаление пакета-замены разрушительно, и это план самого apt:

```
$ apt-get -s remove libdecor-0+stplr-freshlibs
Следующие пакеты будут УДАЛЕНЫ:
  gnome-session-wayland  libdecor-0+stplr-freshlibs  xorg-xwayland
  i586-steam.32bit       mesa-gears
```

Правильный откат — `apt-get install` дистрибутивной версии: обмен проходит в
одной транзакции и ничего лишнего не удаляет. Но на случай прямого удаления
пакет восстанавливает состояние сам. Схема из трёх частей:

| Хук | Что делает |
|:--|:--|
| `postinstall.sh` → `%post` | Записывает в `/var/lib/freshlibs/<пакет>-restore.list` замыкание установленных пакетов, которым нужна библиотека. Снимается при установке и на каждом обновлении. |
| `preremove.sh` → `%preun` | Дополняет список свежим обходом и копирует помощника в `/var/lib/freshlibs`: файлы пакета rpm вот-вот удалит. |
| `postremove.sh` → `%postun` | Передаёт список одноразовой службе `systemd-run --on-active=10s`. |
| `libdecor-restore` → `/usr/libexec/freshlibs/` | Отложенно доустанавливает то, чего не хватает. Подкоманда `consumers` считает замыкание и используется обоими скриптлетами. |

Почему именно так — четыре ограничения, каждое проверено:

1. **apt из скриптлета вызвать нельзя.** Скриптлет исполняется внутри
   транзакции rpm и держит блокировку `/var/lib/rpm/.rpm.lock`. Отсюда
   одноразовая служба systemd, которая стартует после транзакции.
2. **Список нельзя снимать при удалении.** `apt-get remove` сносит зависимые
   пакеты раньше, чем доходит до наших скриптлетов: в контейнере rpm снял
   `mesa-gears` и `xorg-xwayland` первыми, и `%preun` увидел уже пустую базу.
   Поэтому список пишет `%post`, пока система цела.
3. **Фильтр «чего не хватает» живёт в отложенном помощнике**, а не в
   скриптлете: внутри транзакции порядок удаления не определён, и пакет,
   который apt вот-вот снимет, из скриптлета ещё выглядит установленным.
4. **Обмен надо отличать от удаления.** На пути обмена rpm выполняет установки
   до удалений, поэтому в `%preun` системный пакет уже установлен — это и есть
   признак обмена (проверкой файла его не отличить: наш пакет владеет `.so` до
   самого конца). В этом случае скриптлеты молчат и ничего не планируют.

Плюс общие правила для скриптлетов:

- Проверяйте аргумент rpm: `%post` получает 1 при первой установке и 2+ при
  обновлении, `%preun`/`%postun` — 0 при настоящем удалении и 1 при
  обновлении. Без этого восстановление срабатывало бы на каждом
  `stplr upgrade`.
- Никакого `set -e`: уведомление или уборка не должны ронять транзакцию.
- rpm исполняет скриптлеты через `/bin/sh` независимо от shebang, поэтому
  bash-специфичный синтаксис не используется.
- Восстановление **отказывается действовать**, если план apt содержит хоть
  одно удаление: в журнал попадает готовая команда для ручного разбора.
- Опт-аут: `/etc/freshlibs/no-auto-restore`.
- `ldconfig` в скриптлетах — только идемпотентная страховка. ALT-овый rpm
  обновляет `/etc/ld.so.cache` сам (у системных `libcairo`, `libgtk+3`,
  `libwayland-client` скриптлетов нет вообще).

## Проверка

Метаданные собранного пакета:

```bash
rpm -qip  <пакет>.rpm             # Epoch, Version, Release, Group
rpm -qp --provides   <пакет>.rpm
rpm -qp --obsoletes  <пакет>.rpm
rpm -qp --conflicts  <пакет>.rpm
rpm -qp --scripts    <пакет>.rpm  # секции %post, %preun, %postun
rpm -qlvp <пакет>.rpm
```

Главное, что нужно сверить: set-version-provide для soname должен совпадать с
тем, что даёт дистрибутивный пакет (`rpm -q --provides <системный>`).

### Проверка в контейнере

Пакеты-замены не проверяют на живой машине: удаление каскадом уносит
зависимые пакеты, для libdecor — вместе с Wayland-сессией. Нужен одноразовый
контейнер p11, обязательно **с systemd**, иначе отложенное восстановление не
запустится:

```bash
distrobox create --name freshlibs-p11 --image registry.altlinux.org/p11/base:latest \
    --init --additional-packages "systemd rpm apt sudo" --yes

# distrobox enter <имя> -- команда на ALT падает: su: invalid option -- 'm'
podman exec --user root freshlibs-p11 sh -c 'apt-get update'
```

Цикл проверки — шесть шагов:

1. Поставить в контейнере дистрибутивную библиотеку и её потребителей —
   исходное состояние.
2. Установить собранный пакет: системные пакеты должны уйти через `Obsoletes`,
   а `%post` — записать полный список восстановления.
3. Удалить пакет: каскад уносит зависимые, служба должна вернуть **все**
   пакеты из списка одной транзакцией
   (`journalctl -u freshlibs-restore-<пакет>`).
4. Проверить обмен: `apt-get install` дистрибутивной версии — ни
   предупреждений, ни запланированных служб, зависимые не тронуты.
5. Проверить обновление пакета: скриптлеты не должны действовать.
6. Проверить опт-аут: с `/etc/freshlibs/no-auto-restore` восстановления нет.

> [!NOTE]
> `apt-get -s install` для пакета-замены выдаёт ложное
> `E: Fatal, conflicts violated` — симуляция ALT-овского apt не умеет
> разыгрывать пару `Conflicts`+`Obsoletes` на одно имя. Реальная установка
> проходит штатно, ориентируйтесь на неё.

## Добавление библиотеки

1. Создайте каталог, имя которого точно совпадает с полем `name` в рецепте.
2. Положите `Staplerfile` по образцу
   [`libdecor-0/Staplerfile`](libdecor-0/Staplerfile) и скриптлеты по образцу
   соседних файлов.
3. Добавьте `README.md` пакета по образцу
   [`libdecor-0/README.md`](libdecor-0/README.md).
4. Пройдите [цикл проверки в контейнере](#проверка-в-контейнере).
5. Добавьте карточку в раздел «Каталог» и обновите счётчик пакетов в
   [README](README.md).

## Pull request

- Одно изменение — один PR; в описании укажите, что именно проверено и в каком
  окружении.
- Поднимайте `release` при любом изменении рецепта или скриптлетов, иначе
  обновление не дойдёт до установленных систем.
- Контрольные суммы локальных источников (`local:///…`) меняются вместе с
  файлом — не забывайте пересчитывать `sha256`.
